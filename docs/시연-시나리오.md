# 시연 시나리오

영상 촬영용 진행 순서입니다. **위에서부터 순서대로 그대로 따라 하면 됩니다.**
데이터는 `manage.py seed_showcase` 가 깔고, **회의는 촬영 중에 직접 만듭니다** —
첫 장면이 「회의를 잡는 화면」이라 시드가 미리 만들어 두면 그 장면을 찍을 수 없습니다.

- 준비만 하고 싶다 → **A. 띄우기** 와 **B. Discord 잇기** 만 하면 됩니다
- 혼자 동작만 확인하고 싶다 → 그다음 **G. 혼자 테스트** 로 건너뛰십시오
- 다시 처음부터 찍고 싶다 → **H. 초기화**

## A. 띄우기

세 개를 각각 **다른 터미널 창**에 띄웁니다. 셋 다 켜 둔 채로 촬영합니다.

### A-1. 백엔드

```powershell
cd d:\Develop\GitHub\backend
.venv\Scripts\python -X utf8 manage.py runserver 8000
```

`Starting ASGI/Daphne ... at http://127.0.0.1:8000/` 가 보이면 뜬 것입니다.

> `-X utf8` 을 빼지 마십시오. Windows 콘솔이 cp949 라, 한국어가 섞인 출력에서
> 명령이 통째로 죽습니다.

### A-2. 프론트

```powershell
cd d:\Develop\GitHub\frontend
npm run dev
```

`http://localhost:5173` 이 뜹니다. **`127.0.0.1` 이 아니라 `localhost` 로 여십시오** —
Vite 가 `localhost` 에만 붙는 경우가 있습니다.

### A-3. 봇

```powershell
cd d:\Develop\GitHub\backend\bot
.venv\Scripts\python -X utf8 main.py
```

화면에는 아무것도 안 나옵니다(로그가 `bot/discord.log` 로 갑니다). 확인은 이렇게.

```powershell
Get-Content d:\Develop\GitHub\backend\bot\discord.log -Tail 5
```

`연결 완료. 저는 BordoBot입니다.` 가 보이면 된 것입니다.

### A-4. 데이터 깔기

```powershell
cd d:\Develop\GitHub\backend
.venv\Scripts\python -X utf8 manage.py seed_showcase --reset
```

끝에 계정 셋과 촬영 순서가 찍힙니다. **`[주의] Discord 값이 비어 있습니다` 는
지금은 정상입니다** — 다음 단계(B)에서 슬래시 커맨드로 이을 거라서요.

### A-5. 잘 떴는지 한 번에 확인

```powershell
cd d:\Develop\GitHub\backend
.venv\Scripts\python -X utf8 -c "import urllib.request,json; r=urllib.request.urlopen(urllib.request.Request('http://127.0.0.1:8000/api/v1/auth/login', json.dumps({'email':'seoa@demo.bordo.dev','password':'Bordo!2026'}).encode(), {'Content-Type':'application/json'})); print('로그인 OK' if r.status==200 else r.status)"
```

`로그인 OK` 가 나오면 백엔드·DB·시드가 전부 정상입니다.

## B. Discord 잇기 (한 번만 하면 됩니다)

**순서를 지키십시오.** 계정을 먼저 잇지 않으면 팀 연결이 "누구 팀인지 모르겠다"로
실패합니다.

### B-1. 웹에 강태현으로 로그인

`http://localhost:5173` → `taehyun@demo.bordo.dev` / `Bordo!2026`

### B-2. Discord 에서 계정 연결 코드 받기

촬영에 쓸 Discord 서버의 아무 채널에서:

```
/bordo-connect
```

봇이 **DM 으로 6자리 코드**를 보냅니다. (DM 이 안 오면 서버 설정에서
`서버 멤버가 보내는 DM 허용` 을 켜십시오.)

### B-3. 웹에 코드 입력

웹 오른쪽 위 프로필 → `계정` (또는 주소창에 `localhost:5173/account`)
→ `Discord 연결` 칸에 **6자리 코드** 입력 → 연결.

`연결됨` 으로 바뀌면 성공입니다.

### B-4. 서버를 팀에 연결

다시 Discord 에서:

```
/bordo-team-connect
```

`이 서버를 'Bordo 시연팀'에 연결했습니다.` 가 뜨면 끝입니다.

> **팀을 고르라고 나오면** — 강태현이 여러 팀의 소유자일 때입니다.
> 안내에 뜬 `team_id` 를 골라 `/bordo-team-connect team_id:<붙여넣기>` 로 다시.
>
> **`서버 관리 권한이 있는 사람만…`** 이 뜨면 — 그 Discord 서버에서 본인이
> 관리자가 아닙니다. 본인이 만든 테스트 서버에서 하십시오.

### B-5. 다른 참석자도 잇기 (팀원과 같이 찍을 때만)

문도윤 역할을 맡을 사람이 자기 Discord 로 `/bordo-connect` → DM 코드를 받고,
웹에 `doyun@demo.bordo.dev` 로 로그인해 `계정` 화면에서 코드를 입력합니다.

**윤서아는 잇지 않아도 됩니다.** 자리를 비우는 사람이라 Discord 에 안 들어옵니다.

## C. 촬영 전 점검

아래가 하나라도 비면 **회의는 멀쩡히 열리는데 대리인만 조용합니다.**
촬영장에서 원인을 짚기 가장 어려운 실패라 먼저 확인합니다.

| 확인할 것 | 확인 방법 | 없으면 생기는 일 |
|---|---|---|
| `.env` 의 `OPENAI_API_KEY` | A-5 가 통과하면 대체로 정상 | 대리인이 아무 말도 안 합니다. **오류는 안 납니다** |
| 봇이 살아 있는가 | `discord.log` 에 `연결 완료` | 회의 스레드 자체가 안 열립니다 |
| 서버↔팀 연결 | `/bordo-team` 실행 | 봇이 보낸 발언이 어느 팀에도 안 붙습니다 |
| 강태현 계정 연결 | 웹 `계정` 화면이 `연결됨` | 발언의 주인을 못 찾아 아무도 대리하지 않습니다 |
| **원격 봇이 꺼져 있는가** | 서버에서 `systemctl stop bordo-discord` | 슬래시 커맨드에 양쪽이 반응하고, 원격 봇이 **원격 DB** 에 회의를 만듭니다 |

개발 노트북에서 찍으면 `CELERY_TASK_ALWAYS_EAGER=1` 이라 Redis 없이 돕니다.
대신 대리인 실행이 봇의 HTTP 요청 스레드 안에서 일어나 응답이 몇 초 늦습니다 —
**회의 발언 사이에 한 박자 여유**를 두고 말하십시오.

| `taehyun@demo.bordo.dev` | 강태현 | 진행자 · 팀 OWNER · 회의를 만드는 사람 |

비밀번호는 전부 `Bordo!2026` 입니다. 세 계정 모두 `Asia/Seoul` 입니다 — 화면에
찍히는 시각이 사람마다 다르면 보는 사람이 "지금 몇 시 얘기인지" 를 못 따라옵니다.

**대리인은 하나뿐입니다.** 윤서아만 대리 참석하고, 대리인은 Discord 에 별도
계정으로 들어오지 않습니다 — BordoBot 이 `윤서아의 Bordo` 로 대신 말합니다.
그래서 Discord 화면은 **사람 2 + 봇 1** 입니다.

시드에는 **이미 끝난 회의**(`킥오프 · 범위와 일정 합의`, 이틀 전)가 하나 들어
있습니다. 발언 14줄 · 요약 · 플로우 · 브리핑까지 완결된 상태라, 촬영 전에
화면을 미리 보여주거나 "지난 회의는 이렇게 남습니다" 로 쓸 수 있습니다.

## E. 이 시연이 증명하려는 것 하나

> **자리를 비우는 사람이 회의를 위해 추가로 쓰는 글이 없다.**

이게 안 보이면 Bordo 는 "미리 답을 써 두면 대신 읽어 주는 도구" 로 보입니다.
그건 자리를 비우는 사람의 일이 줄지 않으므로 가치가 없습니다. 보여줘야 하는 것은
**이미 있던 기록(작업·계획·문서·일정)만으로 대리인이 답하고, 못 답하는 것만
본인에게 남긴다**는 쪽입니다.

그래서 이 시나리오는 **「회의 전 준비」 화면을 앞에 두지 않습니다.** 논쟁점 예측과
입장 등록은 마지막에 부록으로 붙입니다(장면 7). 순서를 바꾸면 관객 머릿속에
"미리 쓰는 도구" 가 먼저 박히고, 뒤에 무엇을 보여줘도 그 인상이 안 지워집니다.

## F. 장면

### 장면 0 · 문제를 먼저 말한다 (30초, 화면 없이 또는 슬라이드)

기존 방식의 사슬을 그대로 읽습니다.

```
미국 개발자 퇴근 → 한국·베트남 회의 → 질문 발생 → Slack 에 남김
→ 다음 날 출근 → Slack 확인 → GitHub·Notion·회의록 확인 → 상황 파악
→ 답변 작성 → 전달 → 그 다음 날 확인
```

**여기서 "그래서 Bordo 에 미리 입장을 써 두면 됩니다" 라고 말하지 마십시오.**
그 순간 이 시연의 결론이 사라집니다.

### 장면 1 · 회의를 잡는다 — 강태현

**클릭 순서**

1. 웹에 `taehyun@demo.bordo.dev` 로 로그인
2. 홈 「오늘 일정」 오른쪽 위 **`+`** (툴팁 `회의 일정 추가`)
3. 회의 일정 화면에서 **`일정 추가하기`**
4. 팝업 `회의 일정 추가` 에 입력
   - 팀 `Bordo 시연팀` · 프로젝트 `글로벌 회의 도구`
   - 제목 **`API 명세 리뷰`**
   - **날짜는 반드시 오늘, 시각은 지금보다 뒤로** ← 여기가 중요합니다
   - 참여자 셋 다 체크
5. 저장 → 홈으로 돌아오면 「오늘 일정」에 회의가 보입니다

> **오늘로 안 잡으면 장면 2 가 막힙니다.** `회의에 참여하지 않아요` 버튼은
> 「오늘 일정」 행에만 있습니다.

보여줄 것: 회의는 **웹에서 만든다**는 것. Discord 는 회의를 여는 곳이 아니라
회의를 **하는** 곳입니다(봇은 없는 회의를 즉석에서 만들지 않습니다).

### 장면 2 · 자리를 비운다 — 윤서아 (이 시연의 핵심 장면)

**클릭 순서**

1. 로그아웃 → `seoa@demo.bordo.dev` 로 로그인
2. 홈 「오늘 일정」의 `API 명세 리뷰` 행 → **`회의에 참여하지 않아요`**
3. 대리 참석 준비 화면이 열리면 **`불참 등록` 만 누르고 끝냅니다**

**여기서 더 하지 마십시오.**

- 입장을 쓰지 않습니다
- 논쟁점 예측을 돌리지 않습니다
- 대리인 설정도 건드리지 않습니다 (이미 평소 설정이 있습니다)

홈으로 돌아오면 버튼이 **`대리 참석 중`** 으로 바뀝니다. 그게 등록됐다는 표시입니다.

말로 이렇게 붙이십시오.

> "윤서아님이 회의를 위해 추가로 쓴 글은 **한 줄도 없습니다.**
> 지금까지 하던 대로 작업 기록만 남겨 뒀을 뿐입니다."

그리고 `현재 상태` 화면을 잠깐 비춰 **평소에 쌓여 있던 것**을 보여줍니다.

| 종류 | 내용 |
|---|---|
| 작업 | 회의 상세 화면 최종 시안 · 진행 중 · 70% · "브리핑 패널만 남음" |
| 계획 | 디자인 시안 8/18 확정 |
| 문서 | 회의 상세 화면 시안 (Figma) |
| 일정 | 디자인 시안 마감 (확정) |

> **MCP 를 곁들이면 여기가 훨씬 세집니다.** 개인 AI 대화창에서
> `"MCP 연동 붙였어. 기록해 줘"` → `bordo_record_work` 로 작업이 하나 꽂히는
> 장면을 20초만 넣으면, "그럼 이 기록은 누가 쓰냐" 는 질문이 미리 막힙니다.

### 장면 3 · 회의 — Discord

**클릭 순서**

1. Discord 에서 `/meeting-start`
2. 자동완성에 **`API 명세 리뷰`** 가 뜹니다. 고르고 실행
3. 스레드가 열립니다. **이제부터는 스레드 안에서만 말합니다**

발언은 아래 **「대사」** 를 그대로 쓰십시오. 두 장면만 있으면 됩니다.

1. **답한다** — 저장돼 있던 작업·계획을 근거로 대리인이 답합니다
2. **유보한다** — 위임받지 않은 결정이라 답하지 않고 질문으로 남깁니다

> 자동완성에 회의가 안 뜨면 — 스레드가 이미 붙은 회의는 목록에서 빠집니다.
> 회의를 새로 하나 만드십시오(장면 1 반복).

### 장면 4 · 회의를 끝낸다 — Discord

스레드 안에서 `/meeting-end`. 요약 임베드가 붙습니다.

**플로우 진하기는 이때 채워집니다**(`flow.recompute_for_meeting()`). 회의 중에
플로우를 열면 전부 1.0 이라 밋밋하니, 플로우 화면은 **종료 후에** 여십시오.

### 장면 5 · 플로우 — 아무 계정

웹 → 회의 상세 → 플로우 그래프 (주소로는 `/flow-board?meeting=<회의 id>`).

보여줄 것: **사람 노드와 대리인 노드가 갈려 있다.** `윤서아의 Bordo` 에서 나가는
화살표가 곧 "없는 사이 내 대리인이 무슨 말을 했는가" 입니다. 화살표를 누르면
그때 무엇을 근거로 답했는지(Evidence)까지 열립니다.

### 장면 6 · 돌아온다 — 윤서아 (결론 장면)

`seoa@demo.bordo.dev` 로 로그인 → 홈에 브리핑 배지. 열면 네 칸입니다.

| 칸 | 이 시연에서 들어 있는 것 |
|---|---|
| 요약 | 회의에서 정해진 것 |
| 확인이 필요해요 | 내가 없는 사이 바뀐 것 |
| **나에게 요청한 내용** | **일정 연장을 확정해 달라 — 본인만 답할 수 있는 것** |
| 대리인이 답한 내용 | 시안 진행률·마감일. 근거까지 붙어 있음 |

여기서 시연의 문장을 완성합니다.

> "윤서아님이 실제로 읽고 판단해야 하는 건 **한 건**입니다.
> 나머지는 이미 처리됐고, 무엇을 근거로 답했는지도 남아 있습니다."

`답변 대기 질문` 에 답하면 그것이 상대에게 돌아갑니다. 회의는 이미 끝났는데
대화는 이어집니다 — 이게 시차를 건너는 자리입니다.

### 장면 7 · 부록 (시간이 남을 때만)

`회의 대리 참석 준비` 화면 — 논쟁점 예측 · 입장 등록 · 회의별 설정.

**반드시 "더 정확하게 하고 싶을 때 쓰는 것" 으로 소개하십시오.** 필수처럼 보이면
장면 2에서 쌓은 "추가 입력 0" 이 무너집니다.

## 대사 — 회의에서 이렇게 물으십시오

문서 검색이 아직 임베딩이 아니라 **제목·본문 토큰 일치**입니다
(`apps/agent/services/skills/search_records.py`). 질문의 낱말이 저장된 제목을
비껴가면 근거가 `추측(inferred)` 으로만 잡혀 유보로 갑니다
(`judge.py` R3). 그래서 대사는 골라서 씁니다.

### 대리인이 답하는 질문 (장면 3-1)

> **문도윤**: "윤서아님 **시안** 작업 지금 어디까지 됐나요?"

- 왜 도는가 — `시안` 이 작업 제목 `회의 상세 화면 최종 시안` 과 계획 제목
  `디자인 시안 8/18 확정` 에 **제목으로** 걸려 `direct` 가 됩니다
- 기대 답변 — 70% · 남은 것은 브리핑 패널 · 마감 8월 18일
- 대사에 **이름을 넣으십시오.** 대상 판정(`targeting.pick`)이 "이 발언이 누구에게
  향한 질문인가" 를 보는데, 애매하면 **아무도 깨우지 않습니다**(의도된 설계입니다)

이어서 한 번 더 물어도 좋습니다.

> **강태현**: "윤서아님 쪽 **브리핑 패널**은 언제 끝나요?"

### 대리인이 유보하는 질문 (장면 3-2)

> **문도윤**: "디자인이 밀리면 개발도 1주 미뤄야 할 것 같은데, 윤서아님 쪽에서
> 1주 **연장**으로 확정해도 될까요?"

- 왜 유보하는가 — 의도가 `SCHEDULE` 로 분류되고, 윤서아의 설정이
  `allow_schedule_change=False` 라 **LLM 생성 자체를 하지 않습니다**(`policy.check`)
- 기대 발언 — "일정을 미루는 결정은 제가 정할 수 있는 항목이 아닙니다…"
- 이것이 `PendingQuestion` 이 되어 장면 6의 **「나에게 요청한 내용」** 한 건이 됩니다

### 물어도 절대 안 나가는 것 (원하면 보여줄 자리)

> **강태현**: "윤서아님 이번 주 개인 일정은 어때요?"

비공개로 표시한 생각(`이번 주 개인 일정이 빠듯합니다`)은 **설정과 무관하게**
막힙니다(`policy.can_disclose`). 게다가 이 시드는 `disclose_thought=False` 라
**생각은 종류째로 근거에서 빠집니다** — 확정되지 않은 생각을 대리인이 옮기면
"AI 가 내 말을 지어냈다" 로 보입니다.

### 쓰지 말아야 할 대사

| 대사 | 왜 |
|---|---|
| "요즘 어때요?" · "진행 상황 공유 부탁드려요" | `진행`·`상황`·`현황` 은 불용어라 토큰이 안 남습니다. 근거 0건 → 유보 |
| 이름 없이 "이거 언제 돼요?" | 대상 판정이 아무도 안 고릅니다. 대리인이 침묵합니다 |
| "ㅇㅋ", "넵" 같은 짧은 반응 | 질문이 아니라 판정이 걸러 냅니다(정상 동작이지만 화면에 아무 일도 안 일어납니다) |

## G. 혼자 테스트할 때

동작만 확인하는 것이라면 **사람 하나로도 전부 돕니다.** 강태현 하나만 Discord 에
잇고(B-1~B-4), 문도윤 대사까지 강태현이 치면 됩니다. 대리인은 발언자 본인만
후보에서 빼기 때문에, 강태현이 물어도 윤서아의 대리인은 정상으로 답합니다.

최소 경로는 이렇습니다.

```
1. 강태현으로 회의 만들기            (장면 1)
2. 윤서아로 불참 등록                (장면 2)
3. /meeting-start                     (장면 3)
4. "윤서아님 시안 작업 어디까지 됐나요?"     → 대리인이 답하면 성공
5. "윤서아님 쪽에서 1주 연장으로 확정해도 될까요?" → 유보하면 성공
6. /meeting-end                       (장면 4)
7. 윤서아로 로그인 → 브리핑 확인      (장면 6)
```

**다만 이 그림으로 영상을 찍지는 마십시오.** 사람이 하나면 「회의」가 성립하지
않아, 혼잣말에 AI 가 답하는 것처럼 보입니다. 촬영은 팀원 한 명과 함께,
또는 Discord 계정 두 개를 번갈아 쓰십시오.

## H. 초기화 — 테스트한 것 지우고 다시 찍기

```powershell
cd d:\Develop\GitHub\backend
.venv\Scripts\python -X utf8 manage.py seed_showcase --reset
```

시연 팀이 CASCADE 뿌리라 **회의·발언·브리핑·플로우·채팅·문서·발송함까지 한 번에**
사라지고 처음 상태로 돌아갑니다. 개발용 데이터(`@bordo.dev`)는 안 건드립니다.

**Discord 에 남은 것은 서버가 못 지웁니다.** 봇이 만든 스레드와 메시지는 Discord
쪽에 있으니 손으로 지우십시오. 그래서 **테스트는 연습용 채널에서, 촬영은 새
채널에서** 하는 편이 편합니다.

`--reset` 뒤에는 **Discord 계정 연결도 같이 지워집니다**(계정을 지우니까요).
B-2~B-4 를 다시 하십시오. 매번 하기 번거로우면 값을 알아낸 뒤 시드에 실어도 됩니다.

```powershell
.venv\Scripts\python -X utf8 manage.py seed_showcase --reset `
  --guild <서버id> --discord lead=<id> away=<id> member=<id>
```

Discord 에서 개발자 모드를 켜면(설정 → 고급) 서버·사용자를 우클릭해 `ID 복사`
가 뜹니다.

## 대리인이 조용할 때 — 순서대로 보십시오

| 증상 | 먼저 볼 곳 |
|---|---|
| 회의 내내 아무 말도 없음 | `OPENAI_API_KEY` · `bot/discord.log` · 계정 연결(웹 `계정` 화면) |
| 슬래시 커맨드에 반응이 둘 | 원격 봇이 아직 켜져 있습니다. 끄십시오 |
| 특정 질문에만 침묵 | 대상 판정이 아무도 안 골랐을 가능성. **이름을 넣어** 다시 물으십시오 |
| "관련 기록을 찾지 못해…" | 질문 낱말이 저장된 제목과 안 겹칩니다. 위 대사표의 문장으로 |
| "본인 기록이 아닌 자료만…" | 검색이 남의 작업만 물어 왔습니다. `윤서아님` 을 붙여 다시 |
| 답은 하는데 근거가 안 붙음 | 회의 종료 전이라 플로우·브리핑이 아직입니다. 장면 4를 먼저 |
| `/meeting-start` 자동완성이 빔 | 스레드가 이미 붙은 회의는 안 뜹니다. 회의를 새로 만드십시오 |

백엔드 터미널도 같이 보십시오. 봇이 발언을 밀어 넣으면
`POST /internal/v1/discord/messages 200` 이 찍힙니다. **이게 안 찍히면 봇 문제**,
찍히는데 대리인이 조용하면 **판정·정책 문제**입니다.
